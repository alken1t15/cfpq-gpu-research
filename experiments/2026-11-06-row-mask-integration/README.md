# Интеграция маски редукции GPU MxM

Дата: 2026-11-06. Ветка `fix/gpu-mxm-row-mask`, база `6100ad1b1d965111bf6486434eecb73347c3411d`.

## Вопрос и изменение

Проверяем, сохраняется ли результат отдельного explicit-mask trial после полной сборки CFRA и cuBool из изменённых исходников. В `count_nz_pwarp_row` состав участников редукции теперь задаётся выровненной группой `pwarp` lanes, а не текущей сходимостью после циклов разной длины. Shuffle ограничен шириной этой группы. Для текущего вызова pwarp=4, block=256; все четыре потока строки либо выходят вместе, либо участвуют в редукции. Добавлена compile-time проверка допустимого размера группы.

Регрессия `MultiplyDivergentSmallRows` проверяет пять конкретных пар произведения матриц 3×3. Alias-правка и перенос создания tile не интегрированы. Исходный diff и SHA256 файлов: `source.patch`, `manifest.json`. Предыдущие результаты отдельных библиотек остаются в ../2026-11-06-fixed-mask; их нельзя считать результатами этой сборки.

Это проверки корректности без профилировщика, прогрева и измерения ускорения. Завершённые API-вызовы извлечения пар обеспечивают наблюдение результата GPU.

## Вывод и ограничения

Исправление редукции интегрировано и проверено полной CUDA-only сборкой, включая большой внешний luindex. Причина ошибки: динамическая activemask после расходящихся циклов может не включать все потоки строки; фиксированная группа обеспечивает суммирование всех локальных счётчиков. Ранее отдельная guard-проба показала, почему заниженный count опасен также для размера буфера fill.

Общая GPU-корректность не доказана: nonaccumulate alias остаётся отдельной задачей, CLI проверяет количества, а не множества пар. Compute Sanitizer здесь недоступен из-за WDDM, повторно не запускался. Tile-кандидат не включён. Ускорение не заявляется; до performance baseline нужны повторяемость больших входов и отдельное профилирование. Следующие шаги: согласовать alias-контракт; исследовать стоимость incremental/luindex по профилю без смешивания с изменением маски.
