# Проверка CFRA на малых данных FLPQ_Data

Дата: 2026-11-03. Статус: выполнено, **12/12 совпадений**. Не performance baseline.

## Вопрос

Совпадают ли ответы исходного CFRA на двух внешних графах с опубликованными контрольными числами?

## Воспроизведение

```powershell
wsl -d Ubuntu -- python3 /mnt/d/semen_task_avtomat/scripts/catalog-check.py
```

Скрипт скачивает два маленьких архива и контрольную таблицу. Данные лежат в data/catalog-v6/ и исключены из Git. Загруженные файлы не исполняются. Грамматики берутся без изменений из архивов. На каждую грамматику запускаются base/incremental/lazy с явным --cpu, таймаут 60 секунд.

## Формат и семантика

Архивы содержат по одной разреженной матрице на метку. В этих архивах индексы нулевые; преобразование не вычитает единицу. README atom явно требует добавлять обратные рёбра с суффиксом `_r`: для каждого (u,v,label) записывается также (v,u,label_r). Дубликаты не удаляются преобразователем. Пустые пути задаются самими грамматиками, дополнительное epsilon-правило не добавляется.

Размеры проверяются, все ID обязаны входить в [0,n). Дополнительно проверяется, что все n вершин представлены в рёбрах: это предотвращает незаметную потерю изолированных вершин из-за входного формата CFRA. Для этих двух графов условие выполнено; общий импорт графов с изолированными вершинами ещё не решён.

Эталоны из reachable_pairs.csv дополнительно сверены с количеством строк results.mtx в архивах. Эти источники одного датасета не являются двумя независимыми oracle.

## Вывод и ограничения

На этих входах три CPU-алгоритма совпали с опубликованными количествами пар. CLI не выводит сами пары, поэтому совпадение множеств ответов CFRA не проверено. Времена в stdout сохранены для полноты, но один запуск без прогрева и повторов не является замером производительности. Шаблонные грамматики, GPU, большие входы, некорректные данные и все граничные случаи не покрыты.

Следующий шаг: расширить семантические проверки (цепные/epsilon/шаблонные правила), выбрать более содержательные входы и зафиксировать CPU baseline с повторами; отдельно подготовить GPU toolchain.
