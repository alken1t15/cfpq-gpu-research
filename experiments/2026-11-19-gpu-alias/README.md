# GPU MxM с выходом во входную матрицу

При умножении без накопления `CudaMatrix::multiply` очищал выход до чтения операндов. Если выход совпадал с одним из входов, операция теряла данные этого операнда. В ветке `fix/gpu-mxm-alias` такой вызов вычисляет произведение во временную матрицу и переносит готовый результат в выход. Это покрывает совпадение с левым, правым или обоими входами. Случай накопления сохраняет прежний путь.

Проверяется новая Release-сборка CUDA 12.4 для SM 86 в WSL Ubuntu, с отключённым sequential backend. Историческая сборка `gpu-row-mask-integrated` прошла 622/864 проверки. Все 242 несовпадения относились к совпадению выхода со входом без накопления. См. [исходное сравнение](../2026-11-06-row-mask-integration/README.md).

```bash
CFRA_BUILD_DIR=/mnt/d/semen_task_avtomat/build/gpu-mxm-alias bash /mnt/d/semen_task_avtomat/scripts/build-wsl-gpu.sh
python3 /mnt/d/semen_task_avtomat/scripts/validate-gpu-alias.py
```

Матричные проверки сравнивают множества пар, а внешний каталог сверяет количество достижимых пар. Используются существующие графы и грамматики, включая случаи с epsilon. Проверка охватывает малый внешний каталог, а luindex в эту серию не входит. Измерения скорости не проводились.

Сборка и скрипт проверки завершились с кодом 0. Результаты: MxM 864/864, примитивы 24/24, границы 138/138, внешний каталог 12/12. Команды, вывод и хеши сохранены в results.json, boundaries.json и manifest.json.
