# Диагностика нераскрытых индексированных шаблонов

Дата: 2026-11-03. Статус: выполнено. База CFRA 3bc9794a509ca2f40c82b04e6c31e21ef9d1dbf1, ветка fix/indexed-template-expansion, незакоммиченные изменения. Дополнение к исправлению формирования имён, не новый алгоритм.

## Проблема

На raw-метках luindex load_3/store_3 парсер не обнаруживает индексы и молча пропускает шаблонные правила. Результат 7472 выглядит правдоподобно, но не совпадает с эталоном 9677. Предыдущее исправление имени не обнаруживает неподдерживаемый формат само по себе.

## Изменение

В grammar.cpp после поиска индексов добавлено предупреждение stderr, если грамматика содержит символы-шаблоны, а множество найденных индексов пусто. Вывод объясняет, что индексированные правила не раскроются, и приводит пример load_i_3 для load_i. Execution продолжается: в некоторых графах отсутствие индексированных рёбер корректно. В README описаны синтаксис, адаптация Java-меток каталога и пределы диагностики. Частичное совпадение меток это предупреждение не обнаруживает.

Формальный контракт импорта Java-графа: load_k → load_i_k, store_k → store_i_k; обратные рёбра load_r_i_k/store_r_i_k; alloc/assign сохраняются, их обратные получают _r. Матрицы каталога этих проверенных архивов нулевые. Все вершины должны быть представлены edge-list, поскольку явной размерности CFRA не принимает. Подробная таблица преобразования и SHA256 luindex сохранены в предыдущем Java-эксперименте. Универсальный импортёр произвольных категорий пока не реализован.

## Ограничения и вывод

Это предупреждение о возможной несовместимости, не доказательство некорректного входа. Ответы не меняются. Намеренно не превращаем отсутствие индексов в фатальную ошибку. Следующий этап — performance baseline на корректно импортированном luindex и затем профиль. GPU ещё не проверялся.

После серии baseline выполнен тестовый скрипт: 9/9, вывод regression.log. На всех шести baseline-запусках реального luindex stderr пустой и ответ 9677.
