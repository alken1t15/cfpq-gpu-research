# Изолированный CPU fast path для accumulated MxM

Дата: 2026-11-03. Статус: серия завершена, корректность проверена, первый CPU-эффект подтверждён на этом входе.
Гипотеза: не выполнять общее CSR-объединение, если произведение или целевая матрица пусты. Мотивация: ../2026-11-03-mxm-counters/ — 94115 из 96039 accumulated unions имеют пустого участника.

## Реализация и границы

Только CPU sequential SqMatrix::multiply. После вычисления произведения и allocateStorage целевой матрицы:

- Если произведение пустое, accumulated C ∪ ∅ = C: оставить цель.
- Если цель пустая, ∅ ∪ P = P: переместить произведение в цель.
- Иначе использовать прежнее sq_ewiseadd.

Флаги accumulate=OFF не меняются. Проверки выполняются после вычисления P и материализации deferred storage, чтобы не терять отложенные SetElement. P — отдельный временный результат, поэтому входные матрицы используются до изменения цели; необходима дополнительная регрессия алиасинга.

Baseline-библиотека, код основного клона и cuBool submodule не меняются. Генерируется отдельная копия исходного sq_matrix.cpp с сохранением MIT-уведомления; собирается отдельная libcubool.so в build/cpu-empty-union-trial. Остальные объектные файлы взяты из той же baseline-сборки. Две версии запускаются через явно разные LD_LIBRARY_PATH, одним и тем же CFRA-бинарником.

Исходник варианта optimized-sq_matrix.cpp, build-команды build-commands.json, хеши библиотек/бинарника/графа/грамматики manifest.json. Исходный git-клон сохраняет ранее подготовленные незакоммиченные правки парсера; настоящая оптимизация пока только в экспериментальном варианте.

## Методика

До замеров запускаются независимые smoke-ответы, 24 граничных и 12 диагностических проверок под trial-библиотекой; артефакты прежних экспериментов сохраняются и восстанавливаются. Выводы — regression.json и отдельные results.json.

Далее luindex, адаптированный граф, java_points_to.cnf, incremental CPU. Для каждой версии один прогрев и пять измеряемых новых процессов. Порядок baseline/fast_path чередуется по раундам, одновременных измерений нет. Каждому процессу задаётся таймаут 120с, обязателен код 0, stderr пустой и #SEdges=9677. Счётчиков и perf в сравниваемых библиотеках нет. Базовая библиотека проверяется по SHA256 после серии.

wall_seconds — полный процесс по perf_counter. analysis_seconds — напечатанный внутренний AnalysisTime. Прогрев исключается из статистики. Сравниваем медианы пяти повторов, сохраняем min/max и выборочное σ. Старый baseline другой серии не используется в знаменателе: baseline измерен заново здесь, в чередующейся серии.

## Результаты

Сырые повторы: raw.json. Итог: summary.json после завершения. Числа ускорения действуют только для этого CPU backend, входа, алгоритма и среды. Управление питанием, температура и посторонняя пользовательская нагрузка не контролировались.

## Ограничения

Это опытная оптимизация библиотеки, не опубликованный upstream-патч. Нужны прямые проверки полных матричных ответов и алиасинга, затем регрессии на большем наборе задач. CFPQ CLI сравнивает только количество пар. Результат не объясняет производительность CUDA backend и не обещает GPU-ускорение.

## Вывод

На этом CPU-входе пропуск общего объединения с пустым участником сохранил проверенные ответы и сократил медиану полного времени с 13.2408 до 8.2439 с. Это первый измеренный performance-результат проекта. Следующий шаг — расширить набор графов/грамматик и проверить профиль trial; только затем решать о переносе патча в рабочую ветку библиотеки. Отдельно остаётся основная GPU-задача.
