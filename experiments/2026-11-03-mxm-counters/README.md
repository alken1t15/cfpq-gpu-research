# Счётчики accumulated MxM в CPU cuBool

Дата: 2026-11-03. Статус: выполнено успешно; ответ 9677.
Гипотеза из perf-профиля: существенная часть объединений при accumulated MxM может иметь пустое произведение или пустую целевую матрицу.

## Методика

```powershell
wsl -d Ubuntu -- python3 /mnt/d/semen_task_avtomat/scripts/count-cpu-mxm.py
```

Исходные CFRA и cuBool не меняются. Скрипт генерирует копию sq_matrix.cpp со счётчиками и таймером вокруг sq_ewiseadd внутри multiply, компилирует её теми же flags.make, линкует отдельную libcubool.so из неизменённых объектных файлов cuBool и нового объекта. LD_LIBRARY_PATH указывает только инструментированному процессу на build/cpu-mxm-counters. Базовые библиотека и бинарник не перезаписываются, их SHA256 проверяются до/после. Generated source с исходным уведомлением MIT, полные build-команды, manifest и stdout/stderr сохранены здесь.

База CFRA 3bc9794a509ca2f40c82b04e6c31e21ef9d1dbf1 плюс исправление/диагностика парсера, тот же бинарник CPU baseline. cuBool 1d4e760bc0d76906b81c70c505d6b29b4d9d3f11. Ubuntu22.04 WSL2, GCC13.4 Release, incremental, luindex с адаптированными метками, CPU sequential. Условия среды см. предыдущий baseline. Таймер steady_clock только для accumulated union после выделения storage целевой матрицы; он не охватывает spgemm.

Таймер объединений с хотя бы одним пустым участником: 5.2903 с; остальных: 0.1042 с. Эти времена относятся к одному инструментированному процессу; счётчики и таймеры добавляют накладные расходы. sum nrows — размерностная сумма, не аппаратный счётчик реально исполненных инструкций/обходов. nnz просуммированы по вызовам, это не nnz финального ответа.

Точные данные: counters.json; stdout с 9677: query.stdout. Инициализация storage выполняется до чтения целевого nvals, чтобы учитывать отложенные элементы.

## Вывод

Частота пустых участников подтверждена на этом входе. Общее объединение действительно выполняется и занимает заметное измеренное время. Это обосновывает испытание fast path, но не доказывает ускорение ещё не измеренной оптимизированной версии. Следующий эксперимент: отдельно скомпилировать вариант без счётчиков, пропускающий union при пустом произведении/цели, проверить корректность и сопоставимые повторы.

Ограничения: один алгоритм, граф, CPU backend и процесс; нет GPU-измерений. Счётчики глобальные и рассчитаны на данную однопоточную sequential-реализацию, для многопоточного backend потребовалась бы другая агрегация.
