## Вопрос и методика

В успешном luindex ранее было42итерации/112990матричныхвызовов,последние10итерацийзаняли36.806с. Теперь считаем MxM/EWiseAdd/EWiseMulInverted отдельно. Для каждого оригинального MxM через Nvals читается размер входа DM: right в первой фазе, left во второй. delta_sum суммирует размеры по вызовам, учитывая повторное использование пар разными правилами; это не размер объединения дельт. delta_max — максимум размера одного входа DM.

Начиная с33-й итерации перед каждым исходным accumulated MxM дополнительно вычисляется отдельное nonaccumulate произведение в scratch-матрицу, читается его nvals и освобождается scratch. Таким образом tested/empty_products относятся к фактически вычисленному произведению A×B, а не к изменению накопленного результата. Это дополнительные вычисления и GPU-чтения; время такой версии не benchmark, поведение планирования может отличаться. Оригинальная операция выполняется после пробы с прежними входами/флагом. Известный nonaccumulate alias здесь не задействован: scratch distinct от входов.

Производственный incremental_algo.cpp не меняется. Генератор создаёт копию и отдельный hostobject; остальные объекты и baseline cuBool прежние, без metadata/alias/tile/streamreuse. Хеши/compile/link — manifest.json, точный диагностический diff — instrumentation.patch. Проверка неизменности исходников/baseline после запуска встроена в runner.
