# Проверка CUDA-сборки CFRA на FLPQ_Data

В каталоге FLPQ_Data 6.0.0 есть 155 CFPQ-запросов на 113 графах. Для 151 запроса опубликовано число достижимых пар. Запускаем каждый запрос алгоритмами base, incremental и lazy на CUDA-сборке из эксперимента 2026-11-19. Скрипт сверяет SHA-256 исполняемого файла и библиотеки cuBool перед запуском.

## Воспроизведение

В WSL из корня репозитория, после загрузки архива для каждого графа в `data/flpq-all/6.0.0/graph/` и файла `reachable_pairs.csv` в `data/flpq-all/6.0.0/`:

```bash
python3 scripts/check-gpu-flpq-data.py --out data/flpq-all/full-2026-11-21
```

Каталог отчёта должен быть новым. Можно ограничить запуск опциями `--graph` и `--algo`. Лимит по умолчанию 900 секунд на запуск CFRA, включая чтение входов. Архивы читаются последовательно. На диске WSL временно хранится один граф в формате списка рёбер. Скрипт добавляет обратные рёбра, адаптирует индексированные метки, на которые ссылаются шаблоны грамматик и сохраняет размерность графа при изолированных вершинах в конце нумерации с помощью петли с меткой вне грамматик.

В `summary.log` записываются статус и причина по каждому запуску, в `results.jsonl` — также ожидаемое и фактическое число пар и время, в `raw/` — stdout и stderr. Код 0 означает совпадение всех чисел, 1 — хотя бы одна ошибка, 2 — запуск завершился без ошибок, но для части результатов отсутствует эталон. Итоговая строка появляется после завершения серии. Сравниваются количества пар.

## Первичная проверка

На atom и bzip совпали 12 из 12 чисел. Отдельно проверены диагностика несовпадения, отсутствующего эталона, отсутствующего ответа, ошибки процесса и таймаута. Полная серия запущена 21.11.2026. Результаты пишутся в локальный каталог данных.

## Сводка по времени

```bash
python3 scripts/summarize-flpq-timings.py data/flpq-all/full-2026-11-21
```

Команду можно повторять в ходе прогона. В `timings.csv` будет одна строка на запуск с алгоритмом, статусом, размерами входа и двумя временами в секундах. `wall_seconds` включает чтение входов и работу процесса CFRA целиком. `analysis_seconds` берётся из внутреннего таймера CFRA. Подготовка графа из архива выполняется отдельно.

В `comparisons.csv` сравниваются совпавшие с эталоном запуски на одинаковых графе и грамматике. Отношение времени base ко времени incremental или lazy больше единицы, если соответствующий запуск был быстрее. Это отдельные наблюдения. Вывод об устойчивом ускорении потребует повторных запусков.

## Итог исходного прогона

336 совпадений из 465 запусков, 51 расхождение (17 запросов во всех трёх режимах), 60 ошибок выполнения и 18 таймаутов. Для incremental: 114 совпадений, 17 расхождений, 20 ошибок выполнения и 4 таймаута. Четыре запроса без опубликованного эталона завершились ошибками, поэтому отдельный статус no_reference для них не появился. Исходные журналы остаются в data/flpq-all/full-2026-11-21. В восьми журналах ошибок есть сообщение CUDA об исчерпании памяти, в двух — о недопустимом обращении к памяти. Сообщения появлялись при освобождении памяти, точка исходного сбоя пока неизвестна.

## Диагностика индексированных меток

CFRA ожидает `f_i_7` для шаблона `f_i`, а в архиве графа лежит `f_7.mtx`. Старый импорт адаптировал только Java-метки load/store. Теперь он сверяет имена семейств с шаблонами грамматик и сохраняет согласованное обозначение обратных меток. Исходники CFRA и CUDA-библиотека не менялись.

На xz_field_sensitive_alias CPU и CUDA в incremental до преобразования дали 43 242 пары, после — 205 164. Контрольное число совпадает и с CSV, и с заголовком results.mtx в архиве. На jiaozi исходные CPU и CUDA дали 0 пар. После преобразования CPU дал эталонные 14 435 пар, CUDA не завершилась в отдельном 90-секундном диагностическом запуске. Журналы лежат в data/flpq-all/diagnostic-indexed. Это проверка чисел пар. Диагностические запуски не предназначены для сравнения времени.

Повтор с обновлённым импортом на той же CUDA-сборке:

```bash
python3 scripts/check-gpu-flpq-data.py --graph xz --graph xz_field_sensitive_alias --graph nab_field_sensitive_alias --graph atom --algo incremental --out data/flpq-all/indexed-regression
```

6 из 6 совпали с эталоном. Исправлены ответы xz (231 114 → 358 834), xz_field_sensitive_alias (43 242 → 205 164) и nab_field_sensitive_alias (154 406 → 262 566). Три контрольных запроса atom сохранили ответы. Полная серия с новым импортом ещё не запускалась.
