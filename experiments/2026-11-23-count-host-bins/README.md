# Повторное использование метаданных корзин в CUDA count_nz

База — CUDA-сборка с ранним выходом для пустого произведения. Две копии массивов размеров и смещений корзин с GPU на CPU уже выполнялись перед запуском ядер для средних строк. Теперь массивы копируются после построения перестановки, перед всеми тремя путями запуска. Все пути получают константные ссылки на эти массивы. Векторы на устройстве продолжают использоваться при построении перестановки. Сами CUDA-ядра, разбиение строк по корзинам и fill_nz не менялись.

В профиле исходного luindex было 96 039 умножений. Порядок CUDA-вызовов указывал на 126 492 скалярных чтения около pwarp-пути и 96 039 около глобального пути. Гипотеза — переиспользование массивов устранит эти чтения и часть синхронизаций. Сверяем число передач отдельно, по профилированным запускам. Время сравниваем по непрофилированным парным замерам.

```bash
CFRA_BUILD_DIR="$(pwd)/build/gpu-count-host-bins" bash scripts/build-wsl-gpu.sh
python3 scripts/check-gpu-empty-fill-alias.py --count-host-bins
python3 scripts/trace-gpu-empty-fill-luindex.py --count-host-bins
python3 scripts/attribute-luindex-d2h.py data/flpq-all/gpu-count-host-bins-profile/luindex.sqlite --out data/flpq-all/gpu-count-host-bins-profile/d2h-attribution.json
```

Первый скрипт проверяет матричные примитивы, алиасинг и границы умножения, затем pizza/incremental. На luindex сверяются хеши входа и исходной сборки. Один прогрев на библиотеку и пять пар с чередованием порядка, запуск через один и тот же бинарник CFRA, лимит 900 с на запуск. Ожидаем 9 677 пар во всех запусках. После парных замеров снимается полный профиль. Журналы, манифесты и трассы остаются в data/flpq-all.

Сборка и проверки завершились успешно. Проверки MxM 864/864, примитивы 24/24, границы 138/138, pizza 1356. На luindex все прогревы и пять пар вернули 9677. Медиана полного времени уменьшилась с 132,491 до 117,687 с (−11,2%), кандидат быстрее во всех пяти парах. Диапазоны двух серий — 117,462–134,838 с и 114,440–119,936 с. Профиль собран отдельно; в нём также получено 9677.

В новой трассе отсутствуют скалярные чтения до и после двух копий метаданных в окне count_nz, согласно атрибуции по correlationId. На группу по-прежнему приходится два чтения по 36 байт. Число наблюдаемых групп различается: 96039 в исходной трассе и 64267 в новой. Причина не установлена, поэтому разницу общих счётчиков нельзя приписывать только этой правке. Локальные результаты: data/flpq-all/gpu-count-host-bins-profile/d2h-attribution.json и luindex-stats.csv.

## Ночная проверка

```bash
bash scripts/run-count-host-bins-overnight.sh data/flpq-all/overnight-2026-11-24
```

Сначала 21 контрольный запуск новой CUDA-сборки на семи выбранных графах в трёх режимах. Затем на luindex обе библиотеки запускаются через один диагностический бинарник с двумя счётчиками CFRA. На библиотеку выполняются один обычный и один профилированный запуск. Сверяем число пар, итерации, вызовы MxM, число ядер count_nz и копирования по четыре байта. Диагностические замеры времени в сравнение производительности не входят. Диагностический бинарник собирается во временном каталоге, прежние сборки сохраняются.

Очередь запускает этапы последовательно, записывает коды выхода в status.tsv и общий код в exit-code. Первый этап не блокирует независимую диагностику при ошибке. Windows-процесс запуска запросил запрет автоматического сна на время выполнения. Сырые отчёты и трассы остаются в каталоге данных.

Продолжение ночной очереди запускается под той же блокировкой. Условия перехода: 21 успешный контроль, семь совпавших манифестов входов, четыре завершённых запуска luindex с одинаковыми счётчиками итераций и MxM. Далее выполняются пять пар на xz. Если они прошли, собирается отдельная trial-библиотека: в fill_nz после проверки непустого результата пакетом читаются два массива метаданных корзин. Переиспользуются остальные объекты CUDA-сборки count-host-bins. Перед пятью парами luindex выполняются матричные регрессии и pizza. Патч, команды сборки и итог followup-summary.md записываются локально. При сбое очередь останавливается с диагностикой. Кандидат собирается и проверяется в ходе очереди.
