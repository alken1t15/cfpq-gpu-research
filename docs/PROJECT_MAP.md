## Карта

- `src/main.cpp`: аргументы CLI, загрузка, инициализация cuBool, запуск выбранного алгоритма; печатает время и количество пар стартового символа.
- `src/graph/graph.cpp`: формат `src dst label`, число вершин определяется как max ID + 1. Пустой вход и изолированные вершины требуют отдельной проверки семантики.
- `src/grammar/`: загрузка грамматики и расширение шаблонов по меткам графа; подробный аудит ещё впереди.
- `src/base_algo/`, `src/incremental_algo/`, `src/lazy_algo/`: три варианта алгоритма.
- `src/matrix_store/`: хранение матриц и кэш числа ненулевых элементов.
- `src/lazy_algo/chunked_store.cpp`: хранение частями для lazy-варианта.
- `cuBool/`: Git submodule библиотеки булевой линейной алгебры.
- `ci/test.sh`: шесть CPU-проверок: три алгоритма на an_bn (ожидается 20) и transitive_loop (21). Эти эталоны взяты из проекта, не являются ещё независимой проверкой.
- `bench/`: shell runner и список входов. Указанные большие данные не входят в обычный клон.

## Сборка и среда

README указывает Linux (Ubuntu 22.04), C++20, GCC, CMake >=3.15 и CUDA Toolkit для GPU. Корневой CMake указывает 3.10, но cuBool требует 3.15.
CI собирает CPU Release с отключёнными CUDA, тестами самой cuBool и копированием в Python-пакет. Это CPU sequential fallback, а не FastMatrix/GraphBLAS baseline из сравнения автора.

Локально Ubuntu в WSL2 работает, CMake 3.22.1 и GCC 11.4.0 доступны, GPU видна внутри WSL. `nvcc` в PATH WSL не найден. Установка Toolkit в этой сессии не выполнялась.

## Наблюдения, которые влияют на план

README по умолчанию называет incremental, но `main.cpp` фактически задаёт `base`. В экспериментах всегда явно передавать `--algo`, чтобы исключить неоднозначность. Это расхождение документации и кода, не доказанный алгоритмический баг.

Текущий README уже содержит авторские сравнения: ускорение на C alias/VF и замедление на Java/RDF. Их нельзя считать нашими результатами. Постановку из разговора следует уточнять по воспроизведению текущего SHA.

Таймеры в просмотренных реализациях начинаются до построения матриц, но после загрузки графа, расширения грамматики и инициализации cuBool в main. Для GPU ещё нужно проверить синхронность API и границы полного времени. Сейчас измерений GPU нет.

Блоковые матрицы упомянуты в README как план автора. Не выбирать их автоматически: сначала корректность, baseline и профиль на наших входах.

Пример отчёта RodionovMaxim05 подробно фиксирует оборудование, таймауты и ошибки, повторы, графики и ограничения; сырые результаты и скрипты вынесены в benchmark/. Следуем этому принципу оформления, не переносим его числа и выводы на CFRA.
